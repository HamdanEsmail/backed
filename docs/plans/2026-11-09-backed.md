# Backed: build plan

**Goal:** Build Backed as designed in `docs/specs/2026-11-09-backed-design.md`: one line in, a ranked and proved
list of investors out, on one Cloudflare Worker, in the look of `DESIGN.md`.

**Stack:** TypeScript (ESM, strict), Hono 4 with `hono/jsx`, Cloudflare Workers, D1, static assets, a cron every
minute, Vitest in the Workers pool, Wrangler 4. Same versions and conventions as `../standing`.

## Constraints

- Tests never reach TinyFish. Every outbound request goes through an interceptor that throws on a request it was
  not told to expect (copy `../standing/tests/helpers/fetch-mock.ts`).
- **Fixtures are invented.** Fictional companies, investors, people and announcement pages, written by hand in the
  shape of the real responses. The real captures in `../spikes/funding-radar-9nov/` are for reading and are never
  copied into this repository.
- Every limit and price lives in `src/core/limits.ts`. Every TinyFish call writes one ledger row.
- The key is only in `.dev.vars` and in the Worker's secrets. It is never printed or logged.
- No paid TinyFish call while building. Free calls (Fetch, Search, `/v1/datasets/plan`) are allowed for looking
  at real pages. Paid runs happen once, at Task 6.
- The site sits behind `SITE_ENABLED` until it is switched on.
- Copy on the site follows the voice in `DESIGN.md`. The honest-state sentences in the spec are exact.
- Targeted testing: tests for behaviour that can go wrong (the proof check, the score, the state machine, limits,
  input rules), not for markup details. Run the files you touch while working and `npm run check` once per task.

## Things that are easy to get wrong

1. A page that names a different company with a similar name must not prove a row. The company and the investor
   are both looked for, as whole names.
2. An investor named on the page but in a sentence about another round ("previously backed by …") still counts
   today; the quotation shows the reader which sentence it was. Do not try to be clever about it.
3. TinySet rows change while a run is in progress (a row gains fields, two rows merge, a row is removed). Rows
   are stored by their `_id` and re-read; a company is checked again when its announcement URL or investors change.
4. `advance` can be called by the page and the cron at the same moment. Each step claims its work in one SQL
   statement so nothing is checked or paid for twice.
5. A Worker request has a limit on subrequests and CPU. One `advance` does a small, fixed amount of work.
6. The founder's line is shown back on pages and goes into a TinySet prompt. It is escaped on output and limited
   on input.
7. One-word names that are ordinary words (an investor called Headline, True or Neo) match almost any page. They
   count only with their capital letter, as a whole word, in a sentence with a funding word (spec section 5).
8. `advance` must never delay a page. Pages answer from what is stored and start `advance` after the response
   (`waitUntil`); announcement reads time out at 10 seconds.

- [ ] `migrations/0001_init.sql`: `searches`, `companies`, `company_investors`, `investors` (lookups, section 7),

- [ ] `src/search/score.ts`: `rank(companies, founder, today)` (spec section 6), pure.
- [ ] `src/search/advance.ts`: the state machine of spec section 3, with the one-at-a-time slot, the queue, the
